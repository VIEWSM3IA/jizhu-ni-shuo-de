# 版本路线：逐一迭代，不堆功能

## V0.1 — 「锁话」：验证核心闭环

### 目标
验证最小行为链：创建 → 分享 → 押话 → 封存 → 到期 → 开封。

### 必须包含
- 首页“我参与过的”列表
- 创建一句话 + 开封时间
- 群内称呼
- 创建即冻结
- 微信小程序卡片分享
- 同意 / 反对一次性提交
- 截止前仅显示总参与人数
- 到期后参与者可开封
- 开封后显示参与者及原始选择
- 基础登录、异常、并发、撤销规则
- 最小埋点

### 明确不做
- 订阅提醒
- 图片/海报
- 头像
- 评论
- 输赢判定
- 排名/积分
- 群 ID 绑定

### V0.1 验证问题
1. 从群卡片进入后的押话转化是否成立？
2. 一条话平均能带来几个非发起人参与？
3. 无提醒情况下，到期是否仍有人主动回来？
4. “创建即不可修改”是否造成明显误操作投诉？

---

## V0.2 — 「叫回来」：专门解决回访

前提：V0.1 已证明“有人愿意创建和参与”，但到期开封率受回访影响。

### 增量
- 押话/创建成功后，用户主动选择“到期提醒我”
- 使用微信一次性订阅消息
- 首页增加“最近要开封”优先排序
- 待开封角标/轻提示
- 提醒失败与拒绝不影响主链路

### 不做
- 每日提醒
- 营销推送
- 多次催促

### 核心验证
订阅提醒是否显著提升到期开封率，同时不降低押话转化。

---

## V0.3 — 「开封更有戏」：强化回群传播

前提：有稳定开封行为。

### 增量
- 已开封页生成适合截图的“结果卡”布局
- 分享已开封卡片时使用结果态标题
- 一键“再记一句”，带入上次参与称呼
- 开封动画与轻量反馈
- 可选：参与者补一句“结果怎么样了？”纯文本备注（只有当数据证明群讨论需要落在小程序里时才做）

### 坚持不做
- 谁赢了
- 总战绩
- 个人历史胜率

---

## V1.0 Frozen — 可正式上线的稳定形态

### 目标
把 V0.x 的正确行为固化，而不是继续扩张。

### 必须完成
- 隐私协议与最小数据收集说明
- 举报 / 内容安全 / 管理删除通路
- 账号注销与个人数据处理
- API 鉴权、限频、审计
- 并发开封幂等
- 分享失效/撤销/过期边界完整
- 真机 iOS / Android 微信验收
- 弱网与重试
- 关键页面首屏性能
- 埋点口径冻结
- Seed Case 与完整 E2E

### Frozen 后默认不新增一级页面
任何新增功能必须回答：它是否直接提升“创建、参与、到期开封、回群”四个行为之一？否则不进入产品。
