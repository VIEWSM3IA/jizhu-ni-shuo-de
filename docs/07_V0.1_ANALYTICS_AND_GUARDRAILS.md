# V0.1 埋点与指标

## 1. 北极星

**到期开封率**

定义：到期的 Capsule 中，在到期后 7 天内被任一参与者开封的比例。

这是对“大家有没有真的回来找当时证据”的直接验证。

## 2. 核心漏斗

### 创建漏斗
`create_sheet_opened → create_submitted → capsule_created → share_intent`

观察：
- 创建完成率
- 中位创建耗时
- 创建后分享意图率

### 分享参与漏斗
`share_entry_viewed → stance_tapped → alias_completed(if needed) → stance_submitted`

观察：
- 分享入口到押话转化
- 首次 alias Sheet 的流失
- 每 Capsule 非发起人参与人数

### 开封漏斗
`capsule_due_viewed → open_tapped → opened_viewed → reshare_intent`

观察：
- 到期回访
- 到期页面到开封转化
- 开封后回群分享意图

## 4. 事件公共字段

只记录服务端固定值校验后的产品分析字段：
- capsule_id（内部匿名 ID）
- viewer_role: creator/participant/visitor
- capsule_state: JOINABLE/SEALED/DUE/OPENED/INVALID
- entry_source: share/home/direct/reminder
- permission_result: accept/acceptWithAudio/reject/ban/filter/error
- reminder_state: none/armed/sent

`participant_count_bucket`、`time_to_open_bucket`、`client_platform` 和 `app_version` 当前没有固定值 schema，服务端不会持久化；定义允许值后再启用。

禁止把 statement 全文、alias、openid 当埋点属性。

## 5. 决策阈值建议

不是上线 KPI，只用于是否继续迭代的判断：

- 如果分享入口→stance 成功明显低，先修入口与身份摩擦，不做提醒。
- 如果参与正常但开封率低，V0.2 优先订阅提醒。
- 如果开封正常但很少回群，再做 V0.3 的截图/分享结果优化。
- 如果平均非发起人参与长期接近 0，则说明行为本身未成立，不应靠排行榜或积分强行救活。
